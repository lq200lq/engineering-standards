# Lombok

**等级：recommended**

适用于使用 Lombok 的 Java 项目。该规则随 Java 技术栈一并加载，不要求所有项目引入 Lombok。

- 仅在减少重复代码且不遮蔽领域行为时使用注解生成代码；新增 Lombok 依赖应说明其具体收益，并评估 IDE、编译器、静态分析和代码生成工具的兼容性。
- 避免在实体、领域对象或持久化模型上不加判断地使用 `@Data`；逐项选择 getter、setter、构造器、相等性和字符串表示行为。
- 对敏感字段显式排除日志/字符串表示，对关联对象防止递归或意外加载；不要让生成的 `equals` / `hashCode` 破坏 ORM 实体身份语义。
- 构造器注解应与依赖注入和不可变性约定相符；优先让依赖关系在构造时显式可见。
- 对公共 API、复杂行为或会影响安全和数据一致性的代码，优先保留可直接审查的方法实现。
- CI 使用项目统一配置运行注解处理；升级 Lombok 后验证编译、IDE 提示和静态分析结果，并保留移除或替换生成代码的可行性。

参考：[Lombok 功能文档](https://projectlombok.org/features/all)。
