# 成员、角色与权限模型

**等级：recommended**

适用于 Profile 声明 `capabilities.authorization: true` 的项目。

- 将成员身份、角色和权限作为不同概念建模：成员是主体，角色是可分配的权限集合，权限表达可执行的操作；如有组织、租户或资源范围，应把授权范围纳入模型。
- 使用最小权限和默认拒绝；新成员、新角色或未识别权限不得自动获得敏感操作权限。
- 在服务端根据已认证主体、目标资源和操作执行授权。前端菜单、按钮、路由守卫只能改善体验，不能作为安全边界。
- 明确角色分配主体、范围、继承规则、冲突处理和撤销生效时机；避免一个全局角色字符串同时承担身份、组织关系和资源权限语义。
- 对关键操作保留可审计的主体、操作、目标、结果和时间信息；日志需避免泄露令牌、凭证或不必要的个人数据。
- 角色与权限的变更应受控并可追踪；高风险权限授予、批量调整和跨租户操作应有与风险相称的复核或验证。
- 权限检查应覆盖对象级访问，防止仅校验“用户是否具有某角色”却遗漏“是否能访问这个具体资源”。
- 用正向和反向用例验证授权矩阵，包括未登录、无权限、越权访问其他成员/租户数据以及权限撤销后的访问行为。

该规则描述通用授权原则，不强制采用 RBAC、ABAC 或特定身份提供方；选择模型时应匹配权限复杂度和资源边界。
